# Official xAI / Grok bug-report process

Source alignment (public statements from Grok / xAI, 2025–2026):

- Primary path: **Report an issue** / **Report Issue** inside the Grok product.
  - Location: three-dots (⋮) menu next to a response or in the chat interface.
  - Works on grok.com, the Grok app (iOS/Android), and X-integrated Grok surfaces.
- Supporting evidence expected: account email, platform, steps to reproduce, screenshot **or** conversation share link.
- Billing / subscription issues: reply to the receipt email or email support with account email + invoice/receipt number.
- General support contact that surfaces in product guidance: support@x.ai (or the short link the interface provides).
- No public phone support, no public Discord, no guaranteed SLA.

## Agent notes

- Prefer the in-product Report an issue path over email whenever possible.
- When the bug occurs in the current chat, treat that chat as the evidence source. Help the user create a share link of *this* conversation.
- Subscription tier is required for triage value even though the public FAQ does not always list it explicitly.
- System and app information (OS, browser/app version, device model, GPU when relevant) improves engineering triage and should be collected.
- Never invent additional channels.
